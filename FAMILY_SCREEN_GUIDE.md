# Moby Family — экран «Моя семья»

## Что изменено

- Экран семейного дерева приведён к компоновке второго референса: родители сверху, дети ниже, выделение выбранного ребёнка, кнопка подтверждения и нижняя навигация.
- При открытии родителем вкладки «Семья» выполняется `GET /api/family/my`.
- При открытии профиля выбранного ребёнка выполняется `GET /api/children/{child_id}`.
- Если запрос падает (например, backend ещё не развёрнут), приложение использует mock-ответ. Mock не подменяет успешный ответ сервера.
- Авторизация не добавлена. Запросы не передают токены, `Authorization` или самодельные параметры пользователя.

## Где менять значения

- `artifacts/moby-family/src/config/userIds.ts` — `PARENT_USER_ID` и `CHILD_USER_ID`. Поставьте реальные ID, когда они будут известны.
- `artifacts/moby-family/src/mocks/family.ts` — резервные mock-ответы семьи и детей.
- `artifacts/moby-family/src/api/family.ts` — типы API и GET-функции. Здесь же читается `VITE_API_BASE_URL`.
- `artifacts/moby-family/src/App.tsx` — загрузка данных, обработка ошибок и экран.
- `artifacts/moby-family/src/index.css` — внешний вид семейного дерева.

**Важно про `PARENT_USER_ID`:** в присланном контракте `GET /api/family/my` не принимает `userId`, а авторизации нет. Поэтому ID родителя сейчас используется как hardcoded ID выбранного режима в интерфейсе, но не отправляется в запрос как придуманный параметр. `CHILD_USER_ID` используется как ID ребёнка в mock и как `child_id` в запросе подробной информации.

## Подключение backend

По умолчанию запросы идут на тот же origin: `/api/family/my` и `/api/children/{child_id}`. Если backend доступен по отдельному адресу, создайте файл `.env` в `artifacts/moby-family` и укажите:

```env
VITE_API_BASE_URL=http://localhost:8000
```

Замените адрес на фактический адрес backend. После изменения `.env` перезапустите dev-сервер.

## Запуск одной строкой

Из корня проекта выполните:

```bash
corepack pnpm install && corepack pnpm --filter @workspace/moby-family dev
```

Vite выведет локальный URL в терминале. Откройте его в браузере, выберите «Я родитель» и вкладку «Семья».

## Как проверить

1. Пока backend не запущен, откройте «Я родитель» → «Семья»: после неудачного запроса должны отобразиться mock-родители и дети.
2. Выберите ребёнка и нажмите «Подтвердить»: выполняется запрос `GET /api/children/{child_id}`, а при ошибке профиль получает mock-данные.
3. Когда backend будет доступен, убедитесь, что его ответы соответствуют присланному контракту. Успешные ответы используются напрямую.
4. Чтобы сменить hardcoded ID, отредактируйте только `src/config/userIds.ts`. Не меняйте mock ID произвольно, если хотите сохранить совпадение ID между семьёй и ответом `get_child`.

## Примечания

- Если frontend и backend находятся на разных origin, backend должен разрешать CORS для origin фронтенда.
- Запрос `GET /api/family/my` не отправляет `PARENT_USER_ID`, поскольку контракт не описывает способ передачи этого ID. Когда backend определит механизм идентификации без авторизации, его можно добавить в `src/api/family.ts`.


## Windows PowerShell

В корне проекта запустите: `pnpm install`, затем отдельно задайте переменные и запустите Vite:

```powershell
$env:PORT="5173"
$env:BASE_PATH="/"
$env:NODE_ENV="development"
pnpm --filter @workspace/moby-family dev
```

Скрипт `preinstall` использует Node.js вместо Unix-команды `sh`, поэтому установка зависимостей работает в Windows PowerShell. Семейный экран сделан компактнее, кнопка «Подтвердить» должна оставаться видимой над нижней навигацией.
